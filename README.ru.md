# X-HE

Реализация на Go схем хеширования аккаунтов x-vare.com: **XHEE** для email и
**X-HPE** для паролей. English version: [README.md](README.md).

Идея простая. Клиент хеширует email и пароль до отправки, поэтому сервер не
видит ни то, ни другое в открытом виде. Перед записью в базу сервер добавляет
свой шаг с ключом.

| протокол | пакет | защищает | шаг клиента | шаг сервера |
|---|---|---|---|---|
| X-HEE | [`xhee`](xhee) | email | `sha256(lower(trim(email)) + соль)` | `HMAC-SHA256(секрет, клиентский хеш)` |
| X-HPE | [`xhpe`](xhpe) | пароль | `PBKDF2-SHA256(пароль, соль устройства, 100000)` | `bcrypt` от клиентского хеша и pepper |

Пакеты независимы: подключайте только нужный. Остальные модули X-HE, о которых
говорится на сайте (сообщения, звонки), в этот репозиторий не входят.

```
xhee/            протокол для email
xhpe/            протокол для паролей
internal/        общая проверка входных данных
example_test.go  оба протокола в одном сценарии регистрации и входа
```

Браузерная часть — `xhe-client.js` на x-vare.com. Пакет выдаёт те же байты; в
тестах это сверено со значениями, полученными боевым кодом на Node.

## Установка

```
go get github.com/X-Vare/X-Hash-Encryption
```

Нужен Go 1.24+ (клиентский шаг использует `crypto/pbkdf2` из стандартной библиотеки).

## Использование

```go
emails, _ := xhee.NewHasher(os.Getenv("XHE_EMAIL_SECRET"), os.Getenv("XHE_EMAIL_SECRET_OLD"))
passwords, _ := xhpe.NewHasher(os.Getenv("XHE_PEPPER"), []string{os.Getenv("XHE_PEPPER_OLD")})

// регистрация: клиент присылает emailHash, passwordHash и свою соль
storedEmail, _ := emails.Hash(emailHash)
storedPassword, _ := passwords.Hash(passwordHash)

// вход
candidates, _ := emails.Candidates(emailHash) // WHERE email_hash IN (...)
res, _ := passwords.Verify(passwordHash, row.PasswordHash)
if res.OK && res.NeedsRehash {
	// пароль верный, но строка записана со старым pepper, старой схемой или малой стоимостью:
	// вызвать Hash ещё раз и обновить запись
}
```

Клиентские функции (`xhee.ClientHash`, `xhpe.NewSalt`, `xhpe.ClientHash`) тоже
есть в пакетах — для тестов, CLI и всего, что не браузер. Весь путь целиком —
в `example_test.go`.

## Ротация секретов

Новый секрет передаётся в конструктор первым, старые — после него. Новые
записи используют новый секрет, а поиск и проверка пробуют и старые.
`xhee.Hasher.Match` сообщает `legacy`, `xhpe.Hasher.Verify` — `NeedsRehash`:
строки переезжают по мере входов, и когда сообщений больше нет, старый секрет
можно убрать.

## Две схемы для пароля (xhpe)

По умолчанию `xhpe.SchemeHMAC`:

```
xhpe2$ + bcrypt(base64(HMAC-SHA256(pepper, clientHash)))
```

`xhpe.SchemeConcat` — то, с чего начинался x-vare.com: `bcrypt(clientHash + pepper)`.
У неё есть изъян. bcrypt читает только первые 72 байта входа; клиентский хеш —
это уже 64 символа, так что **на результат влияют лишь первые 8 байт pepper**,
остальное отбрасывается. `TestConcatSchemeMatchesNode` в `xhpe` показывает, что два
разных pepper проверяют одну и ту же строку. Схема оставлена для проверки и
миграции существующих строк, не для новых установок.

`Verify` принимает оба формата независимо от настройки записи и ставит
`NeedsRehash` для старого.

## Что это даёт и чего не даёт

- Сервер не получает ни адрес, ни пароль. Если база утекла без секретов,
  восстановить их из неё нельзя.
- Хеш email — ключ для поиска, а не анонимность. Кто владеет базой **и**
  секретом HMAC, может проверять догадки по списку адресов.
- С точки зрения сервера клиентский хеш и есть пароль: кто его украл, тот его
  и отправит. bcrypt защищает хранимую копию, а не запрос. TLS и ограничение
  частоты попыток входа по-прежнему нужны.
- 100 000 итераций PBKDF2 ниже текущей рекомендации OWASP для PBKDF2-SHA256
  как отдельной защиты (600 000). Здесь это лишь клиентское растягивание перед
  bcrypt, а число зафиксировано форматом обмена: чтобы его сменить, нужно
  выдавать новые соли.
- Нормализация Unicode для паролей не выполняется — как и в браузерном клиенте.
  `strings.ToLower` в Go и `toLowerCase` в JavaScript расходятся на нескольких
  редких символах; обычных адресов это не касается.
